01 What this tool does

Connects to a list of Cisco switches — directly or through an SSH bastion — collects interface, PoE, neighbour, VLAN and hardware data, and writes an Excel workbook with a SUMMARY sheet, an INVENTORY sheet, and one sheet per device.

Change risk

The audit is strictly read-only. It issues show commands only and never alters configuration. enable is entered only when USE_ENABLE is set.

Run it when you need to

  • Find reclaimable access ports before buying more switches
  • Produce a port-utilisation figure for a site
  • Inventory modules and optics with serial numbers, for RMAs or refresh planning
  • Spot access-layer drift — missing PortFast, non-standard config register, port-security violations
  • Check PoE headroom before deploying more phones, APs or cameras

Typical runtime is 20–40 seconds per device, ten in parallel by default. A 200-switch estate takes roughly 10–15 minutes with all collectors enabled.

02 Prerequisites

Python3.10 or later. Windows users can skip this — setup.bat downloads a private 3.12 runtime.
Network pathTCP/22 to the bastion, or to every device when running --direct.

Disk~200 MB for dependencies, plus workbook and log space.
ExcelAnything that opens .xlsx. LibreOffice works; conditional formatting is preserved.

A read-only TACACS or RADIUS account is sufficient and recommended. enable is needed only if show commands are restricted at privilege level 1.

03 First-time setup

Windows

setup.bat

Downloads the Python 3.12.9 embeddable runtime into python_runtime\, installs pip, then installs dependencies. Needs internet access once. run.bat calls it automatically when python_runtime\ is missing.

Linux, WSL and macOS

./setup.sh

Creates .venv/ and installs dependencies. Needs Python 3.10+ already present.

Developer install

pip install -e ".[dev]"
pytest -q
Reproducible installs

Both installers prefer requirements.lock.txt when it is present — a cross-platform pinned lock. Delete it to float to the newest compatible releases. Regenerate with: 

uv pip compile requirements.txt --universal \
  --python-version 3.10 --output-file requirements.lock.txt

Verify the install

python -m switch_audit --version
python -m switch_audit --list-collectors

Both print and exit 0 without touching the network.

04 Running an audit

Interactive — recommended for ad-hoc runs

run.bat          :: Windows
./run.sh         # Linux / WSL / macOS

Opens a full-screen form: device file, output name, stale threshold, worker count, credentials, jump host. Live statistics and a log pane during the run, a summary screen at the end. Ctrl+Q quits.

Command line

# Use the jump host from config.yaml
python -m switch_audit --devices devices.txt --output output/site-a.xlsx

# Direct connections, no bastion
python -m switch_audit --devices devices.txt --direct

# Override the bastion for one run
python -m switch_audit --devices devices.txt --jump-host bastion.example.com

# Higher concurrency, 60-day stale threshold
python -m switch_audit --devices devices.txt --workers 20 --stale-days 60

# Verbose, for diagnosing a problem run
python -m switch_audit --devices devices.txt --debug

Unattended and scheduled

Always pass --non-interactive

Without it, a missing credential leaves the process waiting on a prompt that no one will ever answer. 

SWITCH_USER=svc-audit SWITCH_PASS=... \
  python -m switch_audit --devices devices.txt \
    --output "output/audit-$(date +%F).xlsx" --non-interactive

Windows Task Scheduler. Store the credential once, then reference it:

cmdkey /generic:SwitchAudit/User /user:svc-audit /pass
FieldValue
ProgramC:\path\to\python_runtime\python.exe
Arguments-m switch_audit --devices devices.txt --non-interactive
Start inC:\path\to\Access_Switch_Audit

Start in matters: config.yaml, devices.txt, logs\ and output\ are all resolved relative to the working directory.

cron:

0 2 * * 1 cd /opt/switch-audit && ./.venv/bin/python -m switch_audit \
  --devices devices.txt --output "output/audit-$(date +\%F).xlsx" \
  --non-interactive >> logs/cron.log 2>&1

The device list

One IP or hostname per line. Blank lines and # comments are ignored.

# Site A — access layer
192.0.2.11
192.0.2.12
access-sw-03.example.com

05 Credentials

Resolved in this order. The first complete pair wins.

  1. SWITCH_USER / SWITCH_PASS
  2. CREDENTIAL_USER / CREDENTIAL_PASS
  3. Windows Credential Manager, target from credentials.target in config.yaml (override with CREDENTIAL_TARGET)
  4. Interactive prompt — suppressed by --non-interactive

A .env file in the working directory is loaded automatically at start-up. Variables already set in your shell always win. Copy .env.example to .env. 

SWITCH_USER=svc-audit
SWITCH_PASS=your_password
USE_ENABLE=false
# ENABLE_SECRET=...
Handling

.env is gitignored. Credentials are never written to disk by the tool, never exported into the process environment, and never logged.

Enable mode

Used only when USE_ENABLE is truthy (1, true, yes, y) and ENABLE_SECRET is set. If USE_ENABLE is set but the secret is empty, the tool logs a warning and continues at whatever privilege the login provides.

06 SSH host key verification

Set under security: in config.yaml. Applies to the bastion and every device.

PolicyBehaviourUse when
strict Only hosts already in known_hosts are accepted. Hardened environments with a managed known_hosts.
auto-add Trust on first use. Unknown hosts accepted and recorded; a changed key is refused. Normal operation. This is the default.
insecure Accept any key, remember nothing. Lab only. 
security:
  host_key_policy: auto-add
  known_hosts: null        # null = ~/.ssh/known_hosts
  save_host_keys: true

Environment overrides: SWITCH_AUDIT_HOST_KEY_POLICY, SWITCH_AUDIT_KNOWN_HOSTS.

Known limitation

Netmiko does not write host keys back, so under auto-add a device key is verified only once it is already recorded. The bastion key — shared by every connection in the run — is recorded on first use.

To pre-populate for strict:

ssh-keyscan -H bastion.example.com >> ~/.ssh/known_hosts
ssh-keyscan -H -f devices.txt >> ~/.ssh/known_hosts

07 Configuration reference

config.yaml in the working directory, or the path in SWITCH_AUDIT_CONFIG. If no file is found, the tool logs a warning and uses built-in defaults.

Every value is validated at startup. A wrong type, an out-of-range number or a misspelt policy stops the run before anything is contacted, with exit 2 and a message naming the key. Environment overrides are checked the same way. Unknown keys are only warned about. To see the values the tool will actually use: 

python -m switch_audit --show-config

config.yaml references config.schema.json, so VS Code (with the YAML extension) completes keys and flags bad values while you edit.

08 Collectors

Each collector runs one extra show command and adds columns. Switch them under collectors: in config.yaml. Disable what you don't need to shorten the run. 

python -m switch_audit --list-collectors

Failure behaviour

Every collector is best-effort. A platform that doesn't implement a command — a non-PoE switch, a device with no optics — contributes nothing and never fails the device.

09 Reading the output

SUMMARY sheet

One row per device including failures, plus a TOTAL row. Count columns are summed, percentages are recomputed from those sums, and temperature and CPU take the peak rather than a sum.

  • Audit Result — OK, ERROR or NO DATA
  • Error — the failure reason, blank on success
  • Total Ports (phy), Access / Trunk / Routed Ports
  • Connected, Not Connected, Admin Down, Err-Disabled
  • Stale Ports, Ports w/ Errors, PoE Active Ports
  • Uptime, Config Register, Reload Reason
  • PoE Available / Used / Remaining (W), PoE Used %
  • PSUs Present / OK, Inlet Temp (C)

Per-device sheets

One row per interface, around 43 columns with all collectors on. Frozen header and an auto-filter on every column. Port Category is the fastest triage column:

ValueMeaning
connectedUp and in use
powered-deviceUp and drawing PoE
availableDown, no evidence of use, below the stale threshold
stale-unusedDown and meets the stale criteria — a reclaim candidate
disabledAdministratively down
errorerr-disabled
trunk/routedNot an access port

INVENTORY sheet

Every module and pluggable optic across all devices with PID, VID and serial — what you need for an RMA.

Conditional formatting

ColourApplied to
GreenStatus = connected, PoE power > 0
Rednotconnect, err-disabled, any error counter > 0, stale = TRUE, port-security violations > 0, PoE Used % > 85
AmberPoE Used % 70–85, Config Register OK = FALSE, STP Edge = FALSE
Greyadministratively down, MAC Count = 0

How stale is decided

Only for access ports, and only when --stale-days > 0.

  • Administratively down or err-disabled → never stale; they are reported under their own category. Override with audit.stale.include_admin_down.
  • connected → stale if Last input ≥ N days.
  • Otherwise → stale only if all hold: no PoE draw, no LLDP/CDP neighbour, and no learned MACs. The MAC check needs the mac_table collector; disable it with audit.stale.use_mac_table: false.

10 Exit codes

CodeMeaningAction
0 At least one device audited successfully. The workbook was written. Check SUMMARY for ERROR rows.
1 Fatal error, or every device failed. See Troubleshooting.
2 config.yaml or an environment override is invalid. Nothing ran. Fix the key named in the message.

A run where some devices fail still exits 0 and still writes the workbook — partial success is success. Failed devices appear in SUMMARY with Audit Result = ERROR and a reason in Error.

Monitoring

Alert on exit 1, and on the ERROR row count exceeding your tolerance. Exit 0 alone does not mean every device was reached.

11 Troubleshooting

Logs are in logs/debug.log — rotating, 5 MB × 5. Re-run with --debug for verbose console output.

Configuration error: Invalid configuration in … exit 2

Cause

A value in config.yaml, or an environment override, failed validation. Each problem is listed with its key, for example connection.timeout (from CONNECTION_TIMEOUT): Input should be a valid integer.

Fix

Correct the value, or unset the variable named in brackets, then confirm with python -m switch_audit --show-config.

No devices were audited successfully exit 1

Cause

Every device failed. The lines immediately above list each device and its reason.

Fix

Authentication failed — wrong credentials, or the account is locked. Verify by hand with ssh svc-audit@<device>. If you use a bastion, check whether repeated runs locked the account.

TCP connection to device failed — no network path, or an ACL. Check reachability from the host actually running the audit.

Confirm which credential source was used — the log records Using credentials from SWITCH_USER / SWITCH_PASS or Found stored credentials for … (target: …).

Cannot reach jump host X exit 1

Cause

The bastion is unreachable or rejected authentication. The run stops before dialling any device.

Fix
ssh -v svc-audit@bastion.example.com

If the bastion is fine by hand but not here, check security.host_key_policy and whether the key changed.

Host key mismatch

Symptom
Host key mismatch for jump host X: the server presented a key
that does not match the one recorded in known_hosts.
Cause

The host was rebuilt — or the connection is being intercepted.

Fix
Verify before clearing

Confirm the new fingerprint out of band before removing anything. Clearing the entry to "make it work" defeats the check entirely.

ssh-keygen -R bastion.example.com

host_key_policy is 'strict' but no known_hosts file was found

Fix

Populate it with ssh-keyscan (see §6), point security.known_hosts at the right file, or switch to auto-add.

No credentials available and prompting is disabled

Cause

--non-interactive with nothing to use.

Fix

Set SWITCH_USER / SWITCH_PASS, or store the credential under the credentials.target name. Under Task Scheduler, remember Credential Manager entries are per-user — store them as the account the task runs as.

Devices file not found / No devices found in …

Fix

Wrong path, or the file is all comments and blanks. Paths are relative to the working directory — for a scheduled task, that is the Start in field.

<path> is locked (is it open in Excel?) — writing to <path>_<timestamp>.xlsx

Cause

Not an error. The run completed; the workbook was open in Excel, so results were written alongside it rather than lost.

Fix

Close Excel before the next run.

Audit Result = NO DATA

Cause

The device was reached but no interface records could be parsed — usually show interfaces timing out or returning unparsed output.

Fix
  • Raise connection.read_timeout; large stacks can take well over 60 s.
  • Look for 'show interfaces' returned unparsed output; is the TextFSM template available? in the log — that points at TextFSM, not the device.

Missing TextFSM templates

Fix

Templates ship with Netmiko via ntc-templates. If they are missing, reinstall dependencies, or set NET_TEXTFSM to a template directory.

Expected columns are missing

Cause

The collector is off, or the platform doesn't support the command.

Fix

Check --list-collectors, then search the log for the command name — a rejected command is recorded at DEBUG level.

The run is too slow

Fix
  1. Raise --workers. 20–30 is reasonable; the bastion is usually the limit, not the host.
  2. Turn off collectors you don't need — each is one extra command per device.
  3. Lower connection.read_timeout if failures are dominated by unreachable devices.
  4. Lower connection.retries for a fast inventory sweep.

The stale count looks wrong

Cause

Usually mac_table is disabled, so occupied ports look idle — or audit.stale.include_admin_down doesn't match your policy. Review the rules in §9.

Stale Ports in SUMMARY always equals the number of ports categorised stale-unused. If they disagree, that is a bug worth reporting.

Account lockouts

Cause

The audit opens one bastion session per run and multiplexes device channels through it, so a run costs a single bastion login. Persistent lockouts usually mean overlapping scheduled runs.

12 Health checks

Run after any change to the tool, Python, or the environment.

python -m switch_audit --version          # metadata loads
python -m switch_audit --show-config      # config validates
python -m switch_audit --devices one-device.txt \
    --output /tmp/smoke.xlsx --debug      # end to end
pytest -q                                 # 165 tests, with [dev]

A single-device run against a known-good switch is the fastest end-to-end check.

13 Escalation

Collect before escalating:

  • logs/debug.log — the failing run's section
  • The exact command line, and whether --direct was used
  • config.yaml with jump_host and credentials.target redacted
  • The generated workbook, if one was produced
  • Output of python -m switch_audit --version
Handle the workbook as sensitive

It contains serial numbers, MAC addresses, VLAN names and topology detail. Treat it at the same level as a configuration backup.
